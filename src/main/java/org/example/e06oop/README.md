# e06. 객체 지향 프로그래밍 (OOP)

## 1. OOP 개념

객체 지향 프로그래밍은 역할을 가진 객체를 정의하고, 객체들 간의 상호작용으로 프로그램을 구성하는 방식이다. 코드를 처음부터 끝까지 순서대로 작성하는 절차 지향 방식은 기능 하나를 수정할 때 전체를 확인해야 하는 문제가 있었고, 이를 해결하기 위해 공통 기능을 객체 단위로 모듈화하는 OOP가 등장했다.

### 4대 특징

| 특징 | 설명 |
| --- | --- |
| 추상화 | 여러 객체의 공통 속성과 기능을 추출해 상위 개념으로 정의한다 |
| 상속 | 상위 클래스의 속성과 기능을 하위 클래스가 물려받아 사용한다 |
| 캡슐화 | 데이터와 기능의 공개 범위를 제한해 외부로부터 보호한다 |
| 다형성 | 하나의 객체가 상황에 따라 여러 형태를 가진다 (오버라이딩, 오버로딩) |

추상화로 공통 요소를 추출하면 하위 객체가 이를 사용할 수 있도록 상속이 필요해지고, 상속으로 공유하는 범위를 제어하기 위해 캡슐화가 필요해진다.

### SOLID 원칙

| 원칙 | 설명 |
| --- | --- |
| 단일 책임 원칙 (SRP) | 하나의 클래스는 하나의 책임만 가진다 |
| 개방 폐쇄 원칙 (OCP) | 확장에는 열려 있고, 변경에는 닫혀 있어야 한다 |
| 리스코프 치환 원칙 (LSP) | 상위 타입의 객체를 하위 타입 객체로 바꿔도 프로그램은 정상 동작해야 한다 |
| 인터페이스 분리 원칙 (ISP) | 사용하는 쪽에 필요한 기능만 제공한다 |
| 의존 역전 원칙 (DIP) | 고수준 모듈은 저수준 모듈의 구현에 의존하지 않아야 한다 |

### is-a와 has-a

| | is-a | has-a |
| --- | --- | --- |
| 관계 | 상속 ("사과는 과일이다") | 포함 ("자동차는 엔진을 가지고 있다") |
| 구현 | `extends` | 필드에 다른 클래스의 인스턴스를 보관 |
| 결합도 | 높음 | 낮음 |

상속은 결합도가 높아 단순한 코드 재사용 목적으로는 사용하지 않는다. 최근에는 상속보다 포함(composition)을 우선하는 설계를 권장한다.

## 2. 클래스와 인스턴스

- **클래스**: 객체를 만들기 위한 설계도. 하나의 파일에 하나의 클래스를 작성하고, 파일명과 클래스명을 동일하게 한다. 클래스명은 PascalCase로 작성한다.
- **인스턴스**: 클래스를 바탕으로 `new` 키워드를 통해 메모리(힙)에 생성된 실제 객체.
- **레퍼런스**: 인스턴스가 위치한 주소. 변수에는 인스턴스 자체가 아니라 이 주소가 저장된다.

### 클래스의 구성

```java
public class Whale {
    // 필드: 객체가 가지는 데이터
    public String name = "고래";

    // 생성자: 인스턴스를 생성할 때 한 번 호출된다 (작성하지 않으면 기본 생성자가 자동 생성)
    Whale() {}

    // 메소드: 객체가 수행하는 기능
    public void swimming() {
        System.out.println("고래 헤엄");
    }
}
```

### 인스턴스 생성

```java
Whale   whale   =   new   Whale();
 ①        ②          ③      ④
```

| 부분 | 역할 |
| --- | --- |
| ① `Whale` | 변수의 데이터 타입. 클래스를 정의하면 클래스명이 곧 새로운 타입이 된다 |
| ② `whale` | 변수명. 관습적으로 클래스명의 첫 글자를 소문자로 쓴다 |
| ③ `new` | 힙에 새 인스턴스를 생성한다 |
| ④ `Whale()` | 사용할 클래스와 생성자를 지정한다 |

대입 연산자는 오른쪽부터 처리된다. `new Whale()`로 인스턴스를 생성한 뒤, 그 주소를 변수 `whale`에 저장한다.

```java
System.out.println(whale.name);  // 고래
whale.swimming();                // 고래 헤엄
```

필드와 메소드는 `변수명.필드`, `변수명.메소드()` 형태로 접근한다.

### 참조 복사와 새 인스턴스

인스턴스는 `new`를 사용할 때마다 새로 생성된다. `=`로 변수를 대입하면 주소만 복사되므로 같은 인스턴스를 가리킨다.

```java
Whale w1 = new Whale();
Whale w2 = w1;             // 같은 인스턴스를 참조
w2.name = "돌고래";
System.out.println(w1.name);  // 돌고래

Whale w3 = new Whale();
Whale w4 = new Whale();    // 서로 다른 인스턴스
w4.name = "돌고래";
System.out.println(w3.name);  // 고래
```

인스턴스의 값을 변경해도 클래스(설계도)는 변경되지 않는다. 새로 생성하는 인스턴스는 항상 클래스에 정의된 초기값을 가진다.

## 3. static

`static`이 붙은 필드와 메소드는 인스턴스가 아닌 클래스에 속한다. 클래스가 처음 사용될 때 메모리에 하나만 올라가므로 인스턴스를 생성하지 않고 `클래스명.멤버`로 접근할 수 있다.

```java
public class Whale {
    public String name = "고래";      // 인스턴스 변수
    public static int age = 20;       // 클래스 변수
}
```

```java
System.out.println(Whale.age);   // 20
// System.out.println(Whale.name);  // 컴파일 에러: 인스턴스 변수는 인스턴스를 통해서만 접근
```

| | 인스턴스 멤버 | static 멤버 |
| --- | --- | --- |
| 소속 | 각 인스턴스 | 클래스 |
| 개수 | 인스턴스마다 하나씩 | 클래스에 하나 |
| 접근 | `변수명.멤버` (new 필요) | `클래스명.멤버` |

- 모든 멤버를 `static`으로 만들면 메모리를 계속 점유하고 어디서든 접근할 수 있어 오용될 위험이 크다. 따라서 여러 곳에서 공통으로 사용하는 설정값 등에 제한적으로 사용한다.
- `main` 메소드는 JVM이 인스턴스 없이 프로그램의 시작점으로 호출해야 하므로 `static`으로 선언한다.
- `static`은 메모리에 미리 올리는 역할만 하며, 접근 가능 범위는 접근제어자가 결정한다.

## 4. 접근제어자

클래스, 필드, 메소드의 접근 범위를 제한해 캡슐화를 구현한다.

| 접근제어자 | 접근 가능 범위 |
| --- | --- |
| `private` | 같은 클래스 내부 |
| (default) | 같은 패키지 |
| `protected` | 같은 패키지 + 다른 패키지의 자식 클래스 |
| `public` | 모든 곳 |

```java
public class AcceseModifier {
    String strDefault = "Default";               // default: 키워드를 작성하지 않는다
    public String strPublic = "Public";
    private String strPrivate = "private";
    protected String strprotected = "protected";

    public String getStrPrivate() {
        return this.strPrivate;
    }
}
```

- default 접근제어자는 키워드를 생략해서 표현한다. `default`라고 작성하면 컴파일 에러가 발생한다.
- `private` 필드는 같은 패키지의 다른 클래스에서도 접근할 수 없다. 외부에서 값을 읽어야 하는 경우 값을 반환하는 `public` 메소드(getter)를 제공한다.
- 다른 패키지의 자식 클래스는 부모의 `protected` 멤버를 상속받은 멤버로서 접근한다. 부모 클래스의 인스턴스를 새로 생성해 접근하는 것은 허용되지 않는다.

## 5. 리턴 타입

메소드명 앞에 작성하는 타입은 메소드가 반환하는 값의 타입이다.

```java
public void swimming() { ... }            // 반환값 없음
public String getStrPrivate() { ... }     // String 반환
public static int add(int a) { ... }      // int 반환
```

- `return`으로 반환하는 값의 타입은 리턴 타입과 일치해야 한다.
- 반환값이 없으면 `void`를 작성한다. 리턴 타입은 생략할 수 없다.
- `void` 메소드의 결과는 변수에 대입할 수 없다.
- 클래스도 타입이므로 객체를 반환할 수 있다. (예: `public Whale makeWhale()`)

## 6. 오버로딩

같은 이름의 메소드를 **파라미터의 개수나 타입**을 다르게 하여 여러 개 정의하는 것이다. 파라미터 목록을 메소드 시그니처라고 한다.

```java
public class OverloadingOOP {
    public static int add(int a) {
        return a + 1;
    }

    public static int add(int a, int b) {
        return a + b;
    }
}
```

```java
OverloadingOOP.add(1);     // 2
OverloadingOOP.add(1, 2);  // 3
```

컴파일러는 호출할 때 전달한 인자의 개수와 타입을 보고 실행할 메소드를 결정한다. 따라서 호출하는 코드만으로 메소드가 하나로 결정되지 않으면 오버로딩이 성립하지 않는다.

| 기존 `add(int a, int b)`에 추가 | 성립 여부 | 이유 |
| --- | --- | --- |
| `add(int x, int y)` | ❌ | 파라미터 이름만 다름 |
| `add(int a, int b, int c)` | ⭕ | 개수가 다름 |
| `add(double a, double b)` | ⭕ | 타입이 다름 |
| `double add(int a, int b)` | ❌ | 리턴 타입만 다름 |

- `System.out.println()`은 `int`, `String`, `double`, `Object` 등 타입별로 오버로딩되어 있어 어떤 값이든 출력할 수 있다.
- 수행하는 기능이 다르면 오버로딩하지 않고 메소드명을 다르게 짓는다. (예: `add`와 `multiply`)
